# Optimize a file

Rewrites one existing canon file of any kind to SKILL.md § How we write and its kind's reference, keeping every behaviour it carries; "improve X everywhere" runs it file by file.

## Five questions, per line

1. Known? § How we write's cut line covers it, it paraphrases what a script it runs does inside — never when to run it or what its output means — or it repeats a step's done state as a checklist → `dropped: <what covers it>`.
2. Pattern? Delete its domain noun: a mechanism survives → keep · nothing survives → an incident: `dropped`, judged afresh if it recurs.
3. Where? SKILL.md § Where a fact goes names another home → `moved: <home>` · this file → keep · its owner already states it → `dropped: <owner>` · a reason → § How we write's No-reasons line.
4. Workflow? § How we write's numbered-steps line → numbered steps in the owning skill's `cookbook/`, each with its done state.
5. Shorter? The shortest of the four forms that keeps it, the file's own subject, the reader as actor and lead-in dropped; a line already in one of the four forms, with nothing § How we write drops, stays byte for byte.

- Every line moves out → the file goes, per SKILL.md § Changing what's written.

## The trace

- Every old line gets one verdict: `line: <new line's first words>` · `merged: <line>` · `moved: <home>` · `dropped: <owner or reason>`; a run of consecutive `dropped` lines sharing one reason takes it once, its first and last lines quoted · `moved` and `merged` stay one row per fact.
- A line with no verdict → the change does not land.

## A wired tool

- One unit: its floor config, each `~/Code` base checkout's `docs/agents/integrations/<tool>.md`, any other `docs/agents/` file outside the files /setup-matt-pocock-skills and /worktrunk write carrying its facts, and its skill, drafted and traced together, per `references/skills.md` § A tool's skill and its config.
- Before a config key moves or goes → SKILL.md § The claim search on the key, before drafting; a script reading it changes in the same change.
- A repo's `docs/agents/<file>.md` outside `integrations/` and the files /setup-matt-pocock-skills and /worktrunk write, carrying a tool's facts → each fact to its home per `references/skills.md` § A tool's skill and its config and SKILL.md § Where a fact goes; the file goes once nothing stays in it.

## Steps

1. Measure: `wc -c`, and whether it loads always, by `paths:`, or on invocation; a file in a pack `references/vendored.md` names as vendored → stop, rewrite nothing; a block its § Blocks registers → its lines take `line:` verdicts, byte for byte.
2. Draft outside the live file, with its trace. Done when every old line has a verdict.
3. Check the draft against § Traps.
4. Show the user the trace in the reply, old, new and verdict side by side; any change after their approval shown again. Done when the user approves.
5. Install.
6. SKILL.md § The claim search on every dropped or moved name.
7. Report before → after size, and every `dropped` line.

## Traps

- A heading other files cite → search `<file> §` before cutting or renaming it.
- A general clause stays general; a list of named cases opens every case left off it.
- A gate's default branch, and a line saying when the rule changes nothing, are directives.
- A general premise moved into one case's step loses the other cases → keep it where every case reads it.
- An example that settled an ambiguous case goes; its ruling stays as a directive.
- A set a script or sibling emits — reasons, verdicts, exit codes → read the emitter, keep the set complete.
- A claim about code → re-read the code first; dropping "today" from a stale claim makes it permanent.
- A fact moved out → every step relying on it names its new home.
- A norm read as an order, or an order as a norm, changes its strength → keep the strength the old line had.
- An absolute written without `never`, `always`, `only`, `no` or `every` — a ban, "must" → add the marker, or it reads as a default.
- Rendered or symlinked file → edit its source and re-render; never the copy.
