# When an agent may not launch

- A repo's canon keeps a dispatched agent — builder, prover, reviewer — from launching an instance → that agent runs no driven check and claims no reading it did not take.
- Its return carries, marked unrun: the check at the path its dispatch's file list names (none named → the script's body in the return) with the exact command that runs it · for a time criterion, the one command and count that takes both readings, per `measuring.md`.
- Every criterion that check serves stays not exercised, blocked on the launching party; the repo's canon says how that party orders its runs against the change and where its result closes the criterion.
- The launching party follows this skill like any launcher → freshness, an isolated instance, and for a time criterion `measuring.md` whole.
- A check the launching party has only seen pass, on a build already holding the change → reported as never seen failing its assertion.
